# Starter code review

| # | Where | What is wrong | How you would notice | How it was fixed |
|---|---|---|---|---|
| 1 | MongoClient setup | No timezone-aware UTC handling and no startup index setup. | BSON datetimes return naive; duplicate writes remain possible. | Configured UTC-aware PyMongo and idempotent indexes in lifespan. |
| 2 | `compute_late_minutes` | Uses host-local clock fields instead of the IST shift start, floors elapsed minutes before checking grace (so 09:40:01 is incorrectly not late), does not truncate input to whole seconds, and cannot resolve an overnight shift start from the prior day. | Test a 09:40:01 IST epoch input, a fractional-second punch, or a 00:30 IST punch on a 22:00-06:00 shift; results violate R1/R2 or depend on host timezone. | Convert epoch instants to UTC-aware datetimes, derive the relevant IST shift start including the overnight start date, truncate to seconds, compare exact elapsed time with 600 seconds, then floor elapsed minutes only when late. |
| 3 | `compute_work_hours` | Python `round` uses ties-to-even. | A value exactly at a half-cent boundary can round down unexpectedly. | Decimal `ROUND_HALF_UP` on elapsed whole seconds. |
| 4 | `compute_overtime` | Always puts shift end on the record date, so overnight shifts use the wrong end date; it counts overtime below 30 minutes. Its aware IST shift-end value also cannot be subtracted from the naive `datetime.fromtimestamp` values produced by the starter. | Call it with the starter's naive punch-out for a normal shift (timezone mismatch), or test a 22:00-06:00 shift with a 06:40 IST punch-out and a 29-minute overrun. | Use timezone-aware UTC instants, resolve overnight shift end on the following IST date, and count only when the overrun is at least 30 minutes. |
| 5 | `EmployeeIn` | Missing field constraints/date checks and permits identical shift bounds. | Invalid codes, dates, email shapes, or shifts are accepted. | Pydantic constraints and explicit date/shift validation. |
| 6 | `PunchInIn` | Timestamp accepts malformed values and status accepts any string. | Seconds, floats, or `ABSENT` can create a record. | Strict epoch-ms validation and presence-only enum. |
| 7 | `health` | Always returns success without pinging MongoDB. | Stop MongoDB and the probe still says ready. | Actual `ping`, with 503 on driver failure. |
| 8 | `create_employee` | Check-then-insert race with no database unique guarantee; `created_at` is naive and the response does not convert it to the contract epoch-millisecond format. | Send simultaneous creates with one `emp_code`; inspect the stored timestamp and response type. | Unique `emp_code` index with duplicate-key 409 handling; store UTC-aware time and serialize it as epoch milliseconds. |
| 9 | `list_employees` | Offset is `page * page_size`, total ignores department, and there is no input bound or sort. | Page 1 skips the first page; filtered total is wrong. | `(page-1)*page_size`, filtered count, stable sort, bounded query params. |
| 10 | `punch_in` | Unknown employees dereference `None`; falsey timestamp zero becomes now; host timezone is used; no overnight date logic; duplicate check is racy; response exposes an `id`. | Unknown code raises 500; concurrent requests can duplicate; response violates the contract. | Return 404, validate and convert timestamps, apply IST attendance-date rules, rely on the unique index, and omit internal identifiers. |
| 11 | `list_attendance` | Loads and sorts the full filtered result in Python, counts only after materializing it, omits the required `emp_code` tie sort, returns internal `_id` under an `id` field, serializes punch instants as date strings instead of epoch milliseconds, and does not validate dates, status, or pagination bounds. | Use a 100k collection, equal-date rows, or inspect the response against the contract. | Apply filters, sort, count, skip, and limit in MongoDB; return the required stable order and natural-key fields; serialize instants as epoch milliseconds; validate query parameters. |
| 12 | Missing contract endpoints | Punch-out, correction, all analytics, and explain endpoints are absent. | OpenAPI route checks fail. | Implemented all contract routes and MongoDB aggregation pipelines. |

**Reviewed and retained:** the use of the two specified collections and employee `emp_code` as the business identity match the data model. The starter defaults of page 1, page size 20, and a 09:30-18:30 shift also match the contract; the query behavior around them did not.
